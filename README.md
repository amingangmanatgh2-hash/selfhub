# 🐾 SelfHub — پنل ربات تلگرام (نسخهٔ ۲)

یک **ربات همه‌کارهٔ تلگرام** روی **Bot API رسمی** + **پنل وب فارسی** که روی Cloudflare Workers اجرا می‌شود: بدون سرور، بدون VPS، بدون ربات هلپر، بدون اتصال دائمی.

مدیریت گروه و کانال، فیلترها، کپچا، پاسخ‌گو، نوت، زمان‌بند و یادآور، آمار، لاگ مدیریتی و اطلاعیه — همه از پنل یا با دستور داخل چت.

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/amingangmanatgh2-hash/selfhub)

📖 راهنمای دیپلوی: [`DEPLOY.md`](./DEPLOY.md) · فهرست کامل قابلیت‌ها: [`docs/FEATURES.md`](./docs/FEATURES.md)

## ⚠️ نسخهٔ ۲ از صفر بازنویسی شد

نسخهٔ ۱ یک «سلف‌بات» بود: اتصال مستقیم با اکانت کاربری تلگرام، پیام انبوه، اسکرپ اعضا، جوینر خودکار، ویو استوری، تگ‌آل و… . **کار نمی‌کرد** و بخشی از آن هم چیزی بود که من نمی‌سازم.

- **چرا کار نمی‌کرد:** معماری روی اتصال دائمی WebSocket به تلگرام از داخل Durable Object بنا شده بود. Cloudflare فقط سوکت‌های *ورودی* را با `ctx.acceptWebSocket` نگه می‌دارد؛ سوکت خروجی با هر request یخ می‌زند و ایزوله تخلیه می‌شود. ضمناً `startLogin` یک promise معلق می‌ساخت و بدون `ctx.waitUntil` پاسخ را برمی‌گرداند — یعنی همان لحظه کشته می‌شد. نتیجه: لاگین هیچ‌وقت کامل نمی‌شد و رویدادی به موتور نمی‌رسید. توضیح کامل: [`docs/ARCHITECTURE.md`](./docs/ARCHITECTURE.md#چرا-webhook-و-نه-اتصال-دائمی)
- **چرا بخشی‌اش حذف شد:** انبوه‌ارسالی به کاربران، اسکرپ اعضا به‌عنوان تارگت‌لیست، عضویت خودکار، ویو خودکار استوری، و اتوماسیون بازی‌های ایردراپ (فارم/چنداکانتی) اسپم، آزار و تقلب است — نه قابلیت. فهرست و دلیلش: [`docs/REMOVED.md`](./docs/REMOVED.md)

اگر دنبال همان موارد بودی: اینجا پیدایشان نمی‌کنی. در عوض بقیهٔ چیزها واقعاً کار می‌کند. 🙂

## 🚀 ۳ دقیقه تا بالا آمدن

```bash
npm install
cp .dev.vars.example .dev.vars      # BOT_TOKEN و ADMIN_PASSWORD را اینجا بگذار
npm run dev                          # → http://localhost:8787
```

برای دیپلوی:

```bash
npx wrangler login
npx wrangler deploy
npx wrangler secret put BOT_TOKEN     # اختیاری؛ از پنل هم می‌شود
```

بعد سایت را باز کن: **توکن ربات + رمز پنل** را بده، تمام. وب‌هوک خودش ست می‌شود.

> 🔑 توکن را از [@BotFather](https://t.me/BotFather) بگیر. سپس `/setprivacy → Turn off` (وگرنه ربات پیام‌های گروه را نمی‌بیند) و ربات را در گروه **ادمین** کن (حداقل: حذف پیام، اعضا، پین).

### می‌خواهی فقط پنل را ببینی؟

روی صفحهٔ نصب یا ورود، دکمهٔ **«مشاهده با دادهٔ نمایشی»** را بزن — کل داشبورد با دادهٔ نمونه کار می‌کند، بدون توکن و بدون اینترنت.

| | |
|---|---|
| 🛡 **مدیریت** | ضدفلود، ضدتکرار، کلمات ممنوعه (فارسی‌آگاه + regex + wildcard)، فیلتر لینک و لینک دعوت، بزرگ‌نویسی، حجم پیام، نوع رسانه، بن بر اساس نام مشکوک، نردبان اخطار |

| 🔐 **امنیت** | PBKDF2 ۲۱۰k، کوکی HMAC زمان‌ثابت، قفل ورود روی دیسک، CSRF، توکن رمزنگاری‌شده با AES-GCM، `secret_token` وب‌هوک |
| 🖥 **پنل** | RTL فارسی، تیره/روشن، مدیریت چند چت، آزمون فیلتر با متن نمونه، لاگ زنده (SSE)، پشتیبان JSON |

## 🏗 معماری

```
تلگرام ──webhook──▶ Worker ──▶ HubDO (Durable Object + SQLite)
                     ▲              │
پنل وب (static) ─────┘              ├─ موتور: moderation / پاسخ‌گو / دستورات
                                    ├─ زمان‌بند (cron → /internal/tick)
                                    └─ آمار، لاگ، نوت، اخطار، modlog
```

- **Webhook + Cron** به‌جای سوکت دائمی → همان چیزی که روی Workers پایدار است؛ هیچ event ای از دست نمی‌رود چون تلگرام خودش update را دوباره می‌فرستد.
- **یک DO با SQLite** → تنظیمات، آمار و لاگ در همان‌جا؛ بدون KV/R2/D1 و بدون کوئری پر‌هزینه.
- **منطق خالص جدا** (`src/logic/*`) → `rules`، `flood`، `words`، `schedule`، `stats`، `settings` هیچ I/O ندارند و ۸۱ تست unit رویشان اجرا می‌شود.

```
src/
├── index.ts      ← Worker: وب‌هوک، احراز هویت پنل، پروکسی API، cron
├── hub.do.ts     ← HubDO: schema، داده، routes پنل، کش‌ها
├── engine.ts     ← موتور: update → moderation / دستورات / خوش‌آمد / زمان‌بند
├── bot.ts        ← کلاینت Bot API (۴۲۹، backoff، بدون any)
├── types.ts      ← تایپ‌های Telegram و مدل داده
├── tgfmt.ts      ← HTML تلگرام، اعداد فارسی، قالب‌ها
├── util.ts       ← PBKDF2 / HMAC / AES-GCM / ابزار زمان
└── logic/        ← words · flood · rules · settings · schedule · stats
```

## ✅ کیفیت

```bash
npm run check     # typecheck (strict، بدون any) + 77 تست + بیلد
```

- `strict` + `noUncheckedIndexedAccess` + `erasableSyntaxOnly` + `verbatimModuleSyntax`
- تست قرارداد API: `test/panel-api.test.ts` می‌سنجد هر مسیری که پنل صدا می‌زند هم در سرور و هم در دادهٔ نمایشی با همان کلیدها وجود دارد
- حجم باندل ≈ ۱۳۸KB (نسخهٔ ۱ با WASM: ≈ ۲.۴MB)
- CI: [`.github/workflows/ci.yml`](./.github/workflows/ci.yml) روی هر push و PR

### تست بدون اکانت ربات

با `SIMULATE=1` در `.dev.vars` می‌توانی update ساختگی به ربات بدهی:

```bash
curl -s -X POST http://127.0.0.1:8787/api/simulate \
  -H 'x-selfhub: 1' -H 'content-type: application/json' -b cookies.txt \
  -d '{"update":{"update_id":1,"message":{"message_id":1,"date":9999999999,"chat":{"id":-100123,"type":"supergroup","title":"تست"},"from":{"id":7,"is_bot":false,"first_name":"علی"},"text":"این کلاهبرداری است"}}}'
```

این مسیر در پروداکشن فعال نیست (فقط وقتی `SIMULATE=1` ست شده کار می‌کند).

## 💰 هزینه و محدودیت‌ها

- پلن رایگان Workers برای ربات یک گروه کوچک کافی است؛ برای ۲۴/۷ و گروه‌های شلوغ پلن Paid (۵ دلار) لازم است.
- سقف CPU هر فراخوانی ۳۰ ثانیه است؛ اطلاعیه‌ها به همین دلیل تکه‌تکه و در چند دقیقه اجرا می‌شوند.
- آمار و لاگ در DO نگه داشته می‌شود: ۹۰ روز روزانه، ۷ روز ساعتی، ۲۰۰ رویداد اخیر.

## ⚖️ نکته

ربات فقط روی چت‌هایی کار می‌کند که **خودشان او را عضو و ادمین کرده‌اند**. داده‌ای از کاربران استخراج نمی‌شود، پیام انبوه به افراد ناشناس فرستاده نمی‌شود، و هیچ اتوماسیونی برای بازی‌ها/ایردراپ‌ها وجود ندارد. برای مدیریت جامعه‌ی خودت بساز، نه برای آزار بقیه.
